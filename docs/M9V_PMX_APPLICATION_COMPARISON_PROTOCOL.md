# M9V: independent PMX forecasts on historical application data

This is development on all four already inspected M7 NCD/r0 native samples:
DeathStar Social Network and OpenTelemetry Demo, each in colocated and split
placement. All three user operations per sample are retained. Successful M9U
qualification, verified from its artifact bytes, gates this experiment. The
frozen source programs and source archive hashes are checked before preparation.

Each PMX extraction uses the 1,200 calibration requests for one user operation.
This per-operation stratification gives one unambiguous user workload entry;
PMX independently estimates shared native-operation rates within that stratum.
All 12 strata are attempted once, without selecting cases by their forecasts.
OTel uses observed SERVER spans; DeathStar uses the M9U service-boundary rule.
Original request IDs join native data, and the disclosed wrapper carries the
external semantic outcome. This endpoint-assisted adapter is not an automatic
discovery of external success semantics from native traces alone.

The original native-inclusive errors and the independently estimated
conditional-local sensitivity are both retained. Unsupported conditioning or
propagation produces explicit variant abstention. Missing/invalid requests,
operation/error/edge mismatches, bridge exceptions and solver failures stay in
the census. An invalid zero-mass solver object is never a zero-availability
forecast. Supported PCM models are solved twice with the unchanged M9S generic
harness and pinned analyzer; repeats must be valid and agree within 1e-12.

Declared runner allocation and PMX CPU/resource defaults remain unchanged. PMX
does not independently identify latent hardware failure rates, replicated routing
semantics or common-domain processes from this adapter. Observed software errors
can reflect those mechanisms. Do not label this as complete physical-model
discovery, nor import the proposed method's graph or fitted probabilities into it.

The existing M7 static proposed estimator and B2 are refitted from learner files
with their frozen implementations in `full` and `sampled_mixed` observation modes.
The primary comparison uses full observations, while the original sampled mode
is descriptive. Their original B0 uses the same retained calibration selection
as that estimator. An additional endpoint MLE uses every calibration request,
matching PMX's external-request denominator. Baseline observations remain an
additional input to the original proposed/B2 pipeline; PMX uses calibration only.
Input scope and selection differences must remain visible in the report.

Candidate probabilities and abstentions are sealed before the evaluation job
opens the historical evaluator request and health files. The main score is Brier
on the whole test sequence, with signed and absolute mean-prediction error.
The existing stable subset and longer-block sensitivity are descriptive. Scores
and paired PMX-minus-comparator differences retain all operation/campaign keys;
partial-coverage means are not presented as population-wide head-to-head means.
This four-campaign development sample does not establish a confirmatory superiority
or noninferiority result. A separate prospective freeze and fresh acquisition
follow any development changes.

Source acquisition, native parsing, projection, existing-model preparation/fitting,
PMX extraction, representation/local-error conversion and Palladio solving are
recorded separately. Shared parsing cost and different input requirements are not
collapsed into an unsupported end-to-end efficiency claim. Full processing runs
only on GitHub Actions, every experiment job has a 360-minute limit, PMX has a
30-minute per-operation watchdog, and successful and failed outputs are retained
for 90 days. No application data are parsed or fitted locally.
