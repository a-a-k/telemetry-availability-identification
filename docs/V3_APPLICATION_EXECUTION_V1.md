## Frozen execution and analysis

Nine GitHub Actions jobs: 3 prepare exact ordinary roles, 3 physically separate builders, 3 separate model-only replays. Each job has a 10-minute cap; each stage has at most 3 concurrent jobs. Artifacts retain 90 days including failure. Builders receive only the six ordinary files and versioned repository source/declarations; a runtime read/network/subprocess boundary covers all ordinary loading and calculations. Replayers receive only model.json/seal.json, check the seal and reproduce calculation hashes. There are no evaluator/controller/test files. Preparation is a separate trusted role with access to transport metadata only for these ordinary inputs.

Every operation returns all six estimates and five paired gaps, their point/ambiguous status, exact rational limits, input census, missing-coordinate counts, completion-evidence provenance counts and calculation hash. Full category laws and ambiguity certificates stay in remote model artifacts. Local retention is limited to exact compact fit/replay/preparation reports and transport metadata. Each required edge is removed independently in replay; execution must become exactly zero. Equivalent edge order must preserve the complete result. These are structural controls, not evidence that the graph was causally identified.

Resource reports preserve wall/user/system/RSS per job and inner stage elapsed time. Shared acquisition is reused and therefore is not measured as zero-cost fresh acquisition. Cold integration/manual source declarations remain separate from repeated execution. Known failures and any unsupported operation are retained; no arbitrary point is substituted to increase coverage.

This technical candidate does not yet bind final G*, G-ID or the published-predecessor adaptation G0. The point of the run is to establish the actual graph/observation/model/calculation chain and its absences for every application, so final method and support declarations can be frozen before the 240-campaign series.
