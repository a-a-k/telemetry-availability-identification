# Десять внешних операций будущей основной серии

Версия contract v1 для DeathStar/OTel, Petclinic contract v2. Внешний success — корректный обязательный результат всей последовательности за **2.000 s**, от начала первой HTTP-попытки до завершения чтения и проверки последнего ответа. Timeout, invalid JSON, неверный промежуточный ответ и неполный обязательный результат — failure. Один внешний request ID и trace context используются для всех HTTP roots/повторов внутри операции; denominator считает внешнюю попытку ровно один раз. Driver retries/redirects отсутствуют, application retries сохраняются. Отсутствие trace или error span не определяет success.

| Приложение / операция | Полная HTTP последовательность | Обязательный результат |
| --- | --- | --- |
| DeathStar / compose_post | POST /wrk2-api/post/compose | 2xx и исходное acknowledgement; text_only/with_media детерминированы parity workload index. |
| DeathStar / read_home_timeline | GET /wrk2-api/home-timeline/read?user_id=1&start=0&stop=10 | 2xx, JSON list; каждый post содержит string post_id/text. Законный пустой [] или точный upstream Lua-cjson {} разрешён. |
| DeathStar / read_user_timeline | GET /wrk2-api/user-timeline/read?user_id=0&start=0&stop=10 | Тот же контракт timeline; произвольный JSON object или post без обязательного поля отвергается. |
| OTel / browse_product | GET /api/products/OLJCESPC7Z | 200, точный product ID, непустые name/description/picture, categories list, корректный USD priceUsd. |
| OTel / add_to_cart | GET product → POST /api/cart | Product contract проходит; cart возвращает exact уникальный userId и ровно один требуемый product с integer quantity=1. |
| OTel / checkout | GET product → POST cart → POST /api/checkout | Оба prerequisites проходят; nonempty orderId/trackingId, exact заданный shippingAddress, USD shippingCost, ровно один item нужного product/quantity с full product и USD cost. |
| Petclinic / list_owners | GET /api/customer/owners | 200, все 10 исходных владельцев и 13 pets с полями fixture. |
| Petclinic / owner_details_with_visits | GET /api/gateway/owners/6 | 200, полный владелец, pets 7/8, все 4 неизменяемых исходных visits. Empty visits fallback — failure. |
| Petclinic / create_visit | POST /api/visit/owners/1/pets/1/visits | 201 в deadline, правильные id/pet/date/unique marker, независимый SQL audit находит ровно одну запись того же id. |
| Petclinic / list_vets | GET /api/vet/vets | 200, все 6 исходных vets с правильными specialties. |

Money допускает protocol int64 units как целое число или десятичную строку; nanos — integer [0,10^9), валюта USD, отрицательные суммы недопустимы. Quantity boolean/string не принимается за integer. One fresh cart user ID вычисляется из полного внешнего request ID, поэтому смешение кампаний/операций не допускается. Полный payload каждого фактически начатого HTTP шага, его hash, status, offsets, semantic verdict и оставшийся общий budget сохраняются в raw evidence. Если шаг не завершён, сохраняется запись о начатой попытке и transport/deadline error; следующий prerequisite не вызывается.

Это versioned clarification относительно M7: старый driver выдавал каждому из трёх HTTP запросов отдельные 2 s и проверял prerequisites только по status. Frozen M7 source/outcomes не меняются; исторические числа не пересчитываются под новые contracts и не смешиваются с main. Новая OTel проверка полей сверена с pinned source `8c47d47c9ac27710d2b2a153bcd53e483bffe66d`: [cart handler](https://github.com/open-telemetry/opentelemetry-demo/blob/8c47d47c9ac27710d2b2a153bcd53e483bffe66d/src/frontend/pages/api/cart.ts), [checkout handler](https://github.com/open-telemetry/opentelemetry-demo/blob/8c47d47c9ac27710d2b2a153bcd53e483bffe66d/src/frontend/pages/api/checkout.ts), [product service](https://github.com/open-telemetry/opentelemetry-demo/blob/8c47d47c9ac27710d2b2a153bcd53e483bffe66d/src/frontend/services/ProductCatalog.service.ts), [protobuf schema](https://github.com/open-telemetry/opentelemetry-demo/blob/8c47d47c9ac27710d2b2a153bcd53e483bffe66d/pb/demo.proto).

Пределы внешнего oracle: DeathStar timeline contract проверяет форму возвращённых posts, но не доказывает отсутствие пропущенного post в меняющейся ленте; законный пустой результат неотличим от скрытой empty-list деградации без отдельной ground-truth fixture. Compose acknowledgement не доказывает ровно одну durable запись. OTel order response проверяет обязательные поля, но не аудирует реальный платёж/доставку или поздние side effects. Только Petclinic create_visit имеет независимый persistence census, и позднее обнаружение записи не меняет timeout failure и не доказывает точный commit timestamp. Эти ограничения должны присутствовать рядом с claims.

Bounded controls `test_whole_operation_contract.py`: единый trace/ID/deadline для трёх roots; три ответа по 0.8 s дают timeout; неправильный 200 prerequisite останавливает sequence; partial checkout/duplicate cart/wrong user/type reject; DS malformed post reject при допустимых empty representations; реальный маленький HTTP server проверяет normal body и dribble-read deadline. Petclinic deterministic live controls квалифицированы в [runtime report](milestones/PETCLINIC_RUNTIME_QUALIFICATION.md). Обновлённым DS/OTel contracts ещё требуется отдельная live interface qualification до основной серии.
