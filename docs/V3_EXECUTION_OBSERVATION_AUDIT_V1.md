# V3: execution-observation census before selecting a refinement

Question: which execution, timing and replica identities are actually available
for all ten declared operations in the ordinary input role? Expected result:
an exhaustive, outcome-specific evidence census, with missingness and failed
attempts retained. This audit follows the scoped H-EXEC routing intervention;
it neither assumes that L4 eligibility is application readiness nor chooses a
new model by observed prediction errors.

Freeze code, protocol and source/configuration locks before restoring payloads
in Actions. Reuse the exact three ordinary calibration artifacts already bound
in B0-v3 CSV-v2: DeathStar and OTel normal technical data, 80 attempts per
operation; Petclinic colocated/NCD development calibration, 900 per operation.
All 4,080 attempts and ten operations remain in the census. No new traffic,
independent observations, fitted models, PMX runs or main campaigns are added.
The two normal windows cannot establish behavior under faults.

The trusted preparation stage restores only the six ordinary files and verifies
the existing seal. The consumer's read boundary activates before seal/schema
validation and every input read; network/subprocess access and non-ordinary data
are denied. Neither evaluator nor controller artifacts are supplied. Read count
and actual bytes, source transfer, process wall/user/system/RSS are reported.
Application native payloads are interpreted only in GitHub Actions.

For each operation retain total successes/failures/timeouts, native presence,
native error flags, target SERVER presence, actual instance/replica fields and
the exact multiplicity distributions of external roots and target SERVER spans.
Failure and timeout cohorts include trace absences; timeout is a subset of
failure, not an additional denominator. A missing error flag does not establish
semantic success. Missing native or replica identity is not completed using
Docker state, declared routing, or a guessed backend. External boundary parents
are checked against the original request-context derivation; other missing
parents are counted explicitly. Preserve the existing operation graph inventory.

Retain HTTP/RPC status-attribute counts by original field and service-level
native/error/identity coverage. The whitelist's normalized error Booleans do not
distinguish OTLP UNSET from explicit OK; this audit cannot reconstruct discarded
status provenance. No native response code alone becomes the external oracle.

Timing diagnostics use integer nanoseconds and the declared 2-second external
deadline. Count spans ending after that deadline or external completion, root
overlap, and both the sum and union of root intervals. Nested/concurrent span
durations must not be summed as whole-operation latency. Cross-process clock
alignment is an assumption of these diagnostics; span ends after client timeout
do not establish when a database write occurred or a causal failure mechanism.
Keep unsupported/missing observations instead of treating them as zero latency.

Three jobs, at most 10 minutes each, at most three concurrently, Python 3.13.15
and pinned dependencies. Compact reports include exact source/run/head/seals,
every operation, failures and costs; retention is 90 days including failures.
Full source/native archives remain remote. Four bounded artificial tests verify
overlap versus sum, timeout with no error flags, missing traces/identity,
invalid roles/context/census and integer timestamp boundaries.

Completion requires the entire source census, schema/seal agreement, exactly six
ordinary data reads and no blocked access. It does not require good error/trace
coverage, assign a point forecast, prove business adequacy, or admit G*. Outcome
inspection makes these retained data development evidence. The next model's
supported cases and observation assumptions must follow from this inventory,
with separate mathematical and independent application controls.
