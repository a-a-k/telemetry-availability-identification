# Изолированный исходный stochastic fit: Petclinic technical package

Вопрос до fits: принимает ли неизменный finite-state likelihood estimator новый Petclinic learner bundle, сохраняя точный read boundary и корректно различая L7/L4 health? Ожидаемый проверяемый результат — predictions либо explicit absence для всех четырёх операций/шести исходных методов в full и sampled_mixed modes, fit diagnostics, representation limitations, RSS/time и actual read-path audit. Current/transfer predictions должны быть запечатаны до загрузки evaluator. Accuracy sign не является gate. Все данные technical, не main.

Фиксированные источники: семь learner artifacts run 34202539028/head 06e83aa; colocated/NCD — corrected-startup run 34204098497/head 68bf0b8. Restore скачивает только названный learner ZIP и проверяет actual SHA/size, CRC, source head/identity и все sealed files. Ни raw mixed archive, ни evaluator artifact в fit job не скачиваются. Unusable acquisition сохраняется явным отсутствием без fit.

`isolated_stochastic_fit.py` загружает только отдельный analysis JSON, без transitively loaded acquisition config/renewal rates/seeds. Во время verification/loading/preparation/fitting process audit блокирует все неразрешённые data reads, network и subprocess calls. Разрешены ровно семь learner files/seal, analysis settings, Python implementation/library code. Наблюдения test и target calibration отсутствуют физически; current split fit получает только свой bundle, а transfer вызывается только из colocated cell, без второго input.

Estimator остаётся M7 `prepare_mode → fit_exact_model → predict_cell`: исходные thresholds, Beta(0.5,0.5) baseline q, likelihood, 8 optimizer starts, numerical identification guards и шесть методов сохранены. Analysis observation seed 771401, full primary, sampled_mixed diagnostic. Никакого temporal/logistic correction нет. Новый decoder принимает L7OK только при явно объявленном HTTP health; значения raw CSV не переписываются. L4 decoding совпадает с frozen M7 на bounded state controls.

Petclinic known graph включает Gateway/Customers/Visits/Vets/database. Реализованный original-method specialization оценивает target two-path state и совместный residual q остальных зависимостей на baseline; он не оценивает каждый database node отдельно и не использует сохранённый service-edge graph как general typed G. Representation output содержит объявленный dependency graph, inferred target necessity, q и эти ограничения. Это сохраняет исходную no-ML реализацию и не выдаёт scalar residual за полноту исходного формализма.

В prospective analysis settings primary comparator назван PMX_conditional_local по семантической причине: local failure probability условна на отсутствии propagated child error. Primary comparison допускается только там, где native propagation и positive support квалифицированы. PMX_inclusive обязательно остаётся отдельным исходным вариантом; propagated errors могут учитываться им повторно. Swallowed-child errors не переписываются, неподдерживаемый primary forecast остаётся отсутствием. Выбор не зависит от будущей accuracy. Полный main protocol/CI/coverage table ещё замораживается отдельным этапом перед 240 новыми кампаниями; данный interface run не выполняет effectiveness tests.

После fit отдельный read-only процесс инвентаризует только calibration native database constructs для независимого PMX adapter. Он не передаёт PMX наши q/graph/fit и не читает evaluator. Новые observed DB constructs потребуют собственных bounded controls перед PMX application runs; прежние M9S/M9U/M9X controls повторно не отлаживаются.
