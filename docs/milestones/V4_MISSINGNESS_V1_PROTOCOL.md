# Неполные наблюдения на независимой проверочной совокупности

Этот протокол конкретизирует пункт о пропусках [подтверждающей серии](V4_CONFIRMATION_V1_PROTOCOL.md). Источник заранее указан: run `34701084950`, head `1d43c3d5ec7852b4dbedf30b3c9e3e8cfd7e557b`. Код и правила фиксируются, пока закрытые проверочные исходы этой серии ещё не открыты. Автоматический workflow запускается после завершения первичной независимой проверки; вручную считать эксперимент на незавершённой серии нельзя.

Совокупность — все поддерживаемые test-попытки с независимо проверенным HTTP/SQL исходом. Исходные структурные отказы остаются отдельными строками охвата. Проверяется точное совпадение списка попыток и совместных категорий с запечатанной моделью. Совпадение E=Y не служит условием включения: даже противоречащая запись должна остаться в эксперименте. Наличие несовместимостей исходной модели, если они обнаружатся, явно ограничит научный вывод, но не меняет состав первично проверенной совокупности.

**Структура и предикат фиксированы.** Изучается потеря наблюдений состояния после построения графа; это не эксперимент с исчезновением структурных рёбер из всех трасс. Внешний журнал попыток и timely сохраняются. Новые маски накладываются только на известные native-координаты; исходные неизвестные не заменяются догадками.

Уровни — 0, 10, 25, 50, 75, 100% известных native-координат, округление бюджета вниз. Seed 771622. Для каждой операции и механизма применяется один детерминированный порядок скрытия, поэтому уровни вложены:

- **Равномерные координаты:** порядок SHA-256 от seed, request_id и имени координаты.
- **Связанные с отказами:** тот же случайный приоритет делится на 4 для внешних отказов; остальные приоритеты сохраняются. Это правило искусственного генератора пропусков. Исходы не передаются функции вычисления границ или правилу открытия дополнительной информации.
- **Потеря native всей попытки:** случайный порядок request_id, затем координат внутри попытки. Для одинакового точного бюджета допускается одна частично скрытая граничная попытка; её наличие отражается в таблице.

Для каждой комбинации сохраняются исходный и фактический бюджеты, число затронутых попыток, ширина средних идентификационных границ, доля однозначных исходов, количество полностью наблюдённых состояний и обе стороны несовместимости с теми же внешними исходами. Увеличение вложенной маски обязано не сужать границы.

Дополнительные сведения рассматриваются четырьмя фиксированными наборами: selection/admission, результат входного вызова, обязательные завершения, все native-координаты. Для каждого набора восстанавливаются только его искусственно скрытые известные значения. Измеряются число открытых координат, затронутых попыток, устранённых неоднозначностей и новая ширина. Последний набор обязан точно вернуть исходные границы, включая исходную неоднозначность. Наборы имеют разные размеры: эта таблица не объявляется сравнением оптимальности стратегий при одинаковой стоимости. Число координат также не выдаётся за стоимость физической инструментализации.

Используется подготовленная таблица того же точного ядра. Для каждого реально встретившегося сокращённого mask-состояния его границы независимо проверяются перечислением кандидатов и непосредственным исходным предикатом. Это проверка корректности, без заявлений о новом алгоритме или его производительности. Идентификационные границы не являются доверительными интервалами для новой выборки.
