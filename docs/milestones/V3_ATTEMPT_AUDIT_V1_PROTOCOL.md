# Доработка после рецензии: аудит отдельных попыток

Основной вклад: **формализация стохастической модели успешности операций, аналитическое исследование её свойств и границ применимости, автоматическое построение и идентификация по телеметрии**. Эксперименты проверяют эту формализацию. Превосходство над B0 не является условием её научной состоятельности.

Последовательность доработки: установить причины расхождений → обосновать исправление → независимо проверить его → показать последствия неполной наблюдаемости. Этот протокол фиксирует первый этап. Новые подтверждающие кампании и изменение модели зависят от результатов этого этапа; их объём и критерии будут зафиксированы до получения новых исходов.

## Первый результат и совокупность

Первый отчёт содержит таблицу **первичные свидетельства → причина расхождения → затронутое предположение → обоснованное исправление → распространённость причины**. Диагностические признаки могут пересекаться; они не объявляются независимыми причинами без разбора свидетельств.

Аудит использует все 240 исторических кампаний run `34465226083`, scientific head `d857ea65ca9da7fa9ae4ee1198317487475246a7`: 864 000 калибровочных попыток и 800 случаев «кампания × операция», включая 39 случаев без поддерживаемой модели. Имеются 761 сохранённая модель: 641 точечная и 120 интервальных. Результаты этих кампаний уже открыты; этот аудит не является независимым подтверждением.

Порядок исполнения детерминирован по компактному калибровочному сравнению: наибольший интервальный разрыв, его контроль N при тех же размещении и повторе, наибольший точечный разрыв и его контроль; затем полный перечень. Если интервальных случаев нет, используются точечные случаи и следующие контрольные кампании по порядку. Первые четыре кампании каждого приложения доступны отдельным артефактом. Порядок не меняет совокупность и не определяет включение попыток.

Скрипт `scripts/audit_v3_attempts_v1.py prepare` использует только сохранённые компактные числа. Для Y берутся **калибровочные** counts в прогнозе B0; `attempted_census.metrics` относится к проверочной выборке и здесь не используется. Зафиксированный список — `configs/v3_attempt_audit_v1.json`, скалярный пересчёт — `docs/evidence/v3-attempt-audit-design/scalar-census.json`.

## Проверяемый путь данных

1. Проверить исходный GitHub artifact ID, имя, run/head, размер, SHA-256, CRC и состав ZIP по ранее сохранённому архивному манифесту. Обрабатывать полные данные только в удалённом workflow, по одной кампании за раз.
2. Проверить печать ordinary role и её связь с сохранённым графовым прогнозом. Воспроизвести все сохранённые прогнозы и B0.
3. Из исходных requests, health и остановленного native collector повторить замороженную проекцию; потребовать точного равенства requests/probes/native/declarations и диагностик парсинга. Это проверка целостности и реализации проекции, а не независимое доказательство правильности бизнес-метки.
4. Повторить замороженную привязку и потребовать точного равенства сохранённой модели. Отдельно восстановить состояние каждой попытки и потребовать равенства совместных категорий и их частот. Отсутствие модели должно воспроизводиться с прежней причиной.
5. Для каждой поддерживаемой попытки проверить **оба** направления `lower_i <= Y_i <= upper_i`; при полностью известном состоянии дополнительно непосредственно вычислить `E_i == Y_i`. Сохранить все попытки, а не только противоречия. Проверить, что сумма по попыткам точно воспроизводит сохранённые границы и калибровочные counts B0.
6. Для каждого диагностического сочетания сохранить первую попытку и первичные request/response/health/native свидетельства; совместимые записи также сохраняются как иллюстративные контроли. Полные свидетельства остаются в удалённом артефакте, компактные производные диагностические поля и ссылки на записи доступны для отчёта. Первые примеры не используются для оценки частот: частоты считаются по полной совокупности.

Отдельно выводятся число и доля несовместимых попыток, оба направления, полная/частичная наблюдаемость, величины агрегатных разрывов, пересекающиеся признаки ложной пробы/завершения/дедлайна и случаи взаимного погашения ошибок. Снижение 97 → 39 при удалении проверки выбора является локализующей абляцией; eligibility остаётся в достижимости, поэтому 39 не доказывает вторую независимую причину и абляция не является автоматически обоснованным исправлением.

## Классификация и следующие решения

Различаются ошибка первичных данных, ошибка реализации привязки и ограничение концептуальной модели. Например, корректный прежний verdict HAProxy может не быть необходимым условием успеха позднейшего вызова. Кроме того, исходный `_health_sampler` ставит `observed_at` перед чтением Docker и proxy stats: эта метка сама по себе не удостоверяет завершение наблюдения до запроса. Ни кодовая находка, ни корреляция признака с расхождением не подменяют разбор записей. Разделение соответствует [Sargent (2010)](https://www.informs-sim.org/wsc10papers/016.pdf).

После обоснованного изменения выражения успеха или допустимых состояний проверить предпосылки сокращения завершений, достижимость свидетельств и эквивалентность точных представлений. Прежние вычислительные измерения сохраняют смысл для прежней постановки; перенос на исправленную постановку требует проверки.

Подтверждающая серия должна включать обнаруженный механизм и сопоставимые контроли. До запуска фиксируются число кампаний, величины для оценки и критерии. **Все прогнозы, включая PMX и B0, сохраняются до открытия новых проверочных исходов.** Историческое отклонение C12 сохраняется. Повтор всех 240 кампаний заранее не предписан.

Эксперимент с неполной наблюдаемостью проводится на записях, проверенных по первичным свидетельствам, без отбора по `E=Y`. Зафиксировать уровни и механизмы пропусков, включая связанные с отказами; оценить ширину границ, долю однозначных результатов, совместимость с внешними исходами на той же совокупности и сведения/число наблюдений, снимающих неоднозначность. Новая стратегия выбора наблюдений не становится обязательной самостоятельной задачей. Если компактная демонстрация уже заданного правила полезна, сравнивать её с фиксированным и случайным правилом при равном бюджете, без доступа к скрытым на момент выбора данным. Идентификационные границы отделять от статистических гарантий новой выборки; общую основу частичной идентификации атрибутировать [Beresteanu, Molchanov, Molinari (2012)](https://sites.pitt.edu/~arie/PDFs/partial_identification_using_random_set_theory_JoE2012.pdf).

Воспроизводимость включает ограниченный пример полного пути исходная запись → проекция → состояние → границы и объяснение совпадений PMX/B0 по фактически построенным PCM-моделям. Работа ведётся в коде, Markdown и таблицах; экспорт рукописи не входит в этот этап. Исходные 356 научных locks, тег v1 и прежние результаты не переписываются.

## Выполнение

Удалённый workflow: `.github/workflows/v3-attempt-audit-v1.yml`. Три задания по приложениям, каждое сначала публикует компактный результат первых четырёх кампаний, затем автоматически завершает остальные 76. Код аудита не включён в измерение производительности. Ошибки целостности останавливают соответствующее задание и сохраняются явным артефактом; они не становятся научными отсутствиями.
