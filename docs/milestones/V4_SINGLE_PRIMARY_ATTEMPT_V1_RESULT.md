# Воспроизводимый путь от первичных записей до модельного состояния

Сохранён один фиксированный исторический пример `DeathStarBench / split / NC / r1 / compose_post`, trace `ab001a37f5166863`. Это иллюстративный контрпример, выбранный после исторического аудита; он не является новой проверочной выборкой или оценкой вероятности для популяции.

В [капсуле первичных записей](../evidence/v4-single-primary-attempt-34702693646/input/) находятся одна внешняя попытка с первичным HTTP-свидетельством, одна исходная Jaeger-трасса из 29 span, 15 первичных записей проверок состояния (пять моментов наблюдения), декларации и спецификация операции. Для каждого исходного объекта указаны SHA оригинального файла, положение объекта в нём и SHA канонического объекта. Отдельная печать фиксирует точные байты восьми файлов капсулы. Полные кампании для повторения примера загружать не требуется.

Последовательность свежего процесса: **проверка первичных байтов → штатный Jaeger-парсер → допустимая проекция телеметрии → обнаружение графа → исходная и исправленная привязки → независимая проверка внешнего исхода**. Никакого отбора наблюдений при повторении не происходит.

Результат [удалённого воспроизведения](https://github.com/a-a-k/telemetry-availability-identification/actions/runs/34702693646): внешний успех подтверждён; исходное полностью установленное событие равно **0**, исправленное — **1**. В исходном состоянии выбранная реплика b имеет отрицательную последнюю proxy-проверку, но приём фактического вызова этой репликой непосредственно подтверждён native-свидетельствами. Завершения и срок соблюдены. [Полный результат](../evidence/v4-single-primary-attempt-34702693646/result.json) содержит обнаруженные сервисы и рёбра, оба состояния и свидетельства расчёта. Числа 0 и 1 здесь — значения события одной попытки, а не утверждение о доступности системы 0% или 100%.

Повторить из сохранённой капсулы одной командой:

```powershell
gh workflow run v4-single-attempt-reproducer-v1.yml --ref main -f source=retained
```

Для повторного извлечения этого же объекта из полного исторического архива предусмотрен `-f source=original_archive`. Оба пути исполняют один проверяющий скрипт в новом процессе GitHub Actions; локально выполняется только просмотр сохранённых данных и результатов. Метод и исходный научный код защищены прежними блокировками.
