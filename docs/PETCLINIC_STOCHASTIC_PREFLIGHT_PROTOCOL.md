# Petclinic: восемь технических stochastic условий

Вопрос до запуска: выдерживает ли квалифицированный v3 runtime полный 4 RPS режим и все восемь placement/law условий с полным census попыток, корректно наблюдёнными faults и отдельно запечатанными learner/evaluator данными? Ожидаемый результат acquisition этапа — восемь manifest/quality records и 32 operation cells, включая все неуспехи. Затем на тех же данных проверяются интерфейсы обоих методов; новый сбор для этой проверки не требуется.

Предварительное доказательство: run 34201555957/head 301756d39fa6aec8b110dd1d89d0228282684e7c, v3 bootstrap прошёл все semantic/native/one-path/TCP-counterexample checks, 192 попытки. [Exact qualification](evidence/petclinic-v3-34201555957/bootstrap-summary.json) закреплена SHA в конфигурации. Используется тот же image ID и verified build archive; source/JAR не пересобираются.

Одна техническая матрица: Petclinic × colocated/split × N/NC/ND/NCD × один повтор = **8 кампаний, 32 operation cells**. Все четыре операции равновероятно по фиксированным количествам, общий поток 4 RPS, 16 workers. Baseline 60 s (60 requests/op), calibration 900 s (900/op), test 900 s (900/op), всего **7440 попыток на кампанию, 59 520 на пакет**. Whole-operation deadline 2 s и v2 semantics неизменны. Между периодами 70 s без faults для обычного восстановления breaker; это время не входит в объявленный 900 s test, и его стоимость учитывается. Trace flush 20 s. Новые base seed 771301 и request namespace содержат run/attempt/placement/law; будущая main series обязана иметь другие seeds.

Законы renewal взяты из закреплённого исходного M7 конфигурационного процесса, без использования его результатов: individual up=12+Exp(mean23), down=Uniform[5,9]; communication up=20+Exp(mean35), down=Uniform[4,8]; common domain up=30+Exp(mean45), down=Uniform[6,10]. N включает две individual pause причины; C — независимое отключение application network каждой реплики; D — pause причин по объявленным logical domains. Colocated обе реплики в domain_a, split в domain_a/domain_b. Домены логические на одном runner; физических host-failure экспериментов нет. БД/telemetry networks при communication сохраняются. Сопутствующие pause/disconnect причины объединяются исходным audited controller; завершение одной причины не восстанавливает реплику при другой активной причине.

Health sampler 1 s читает фактический Docker state и HAProxy HTTP backend status, а не planned schedule. Все injection events/seeds находятся в raw/auditor зоне. **L7OK сохраняется как наблюдение**: старый M7 L4-only decoder использовать для этого стенда нельзя; новый learner adapter должен явно признать заявленный HTTP check. Это изменение интерфейса наблюдений, не подстановка P=1. Все non-target зависимости Gateway/Customers/Vets/DB/proxy перечислены в deployment вместе с происхождением из исходных controllers/clients/SQL, отдельно от trace-derived service edges.

Все попытки, payload hashes, final outcomes, timeout и write-side-effect counts остаются в raw evidence. SQL audit после каждого периода подтверждает exactly-once marker и не превращает timeout в успех. Learner получает только baseline/calibration request rows, calibration health, declaration/topology и calibration-native spans; test request/health files идут в отдельный evaluator artifact. Каждый bundle имеет файл SHA seal. Qualification читающий raw evidence не выполняет model fits. Нулевая фактическая загрузка evaluator при последующем fit должна быть проверена отдельным learner процессом, а не заявлена только по этому разбиению.

Технические gates: точные 240/3600/3600 counts и unique IDs, baseline success ≥0,95 для каждой операции, successful calibration linkage ≥0,95, health observation ≥0,95 и без malformed rows, обе replica identities, все planned fault transitions подтверждены и released, отсутствие активных причин в конце, чистый native parse. Это заранее заданные quality gates; **нет** gate по преимуществу метода, малости prediction error или знаку контраста. Failed cells сохраняются и перечисляются; не заменяются молча другими seeds.

Acquisition занимает минимум 1860+140+20=2020 s на runner плюс восстановление образа/startup/packing; восемь jobs параллельно. Реальные stage/RSS/bytes измеряются, по ним уточняется ресурсная оценка будущих 240 кампаний. Здесь model fits=0 и main campaigns=0: это первый этап одного technical package. До main freeze требуется отдельная проверка обоих методов/семантики/изоляции на этих сохранённых learner bundles. Все heavy действия — только GitHub Actions, timeout 360 min, raw/failures retention 90 days.
