## Реализованный класс и происхождение каждой сущности

Состояние x ∈ {0,1}^d, 1 ≤ d ≤ 16. Pθ(x)=∏ θ_i^{x_i}(1−θ_i)^{1−x_i}; предполагается стационарный закон с 0<θ_i<1 в линии идентификации. Пограничные частотные оценки 0/1 допустимы как plug-in MLE. Событие доступности реплики — конъюнкция её объявленных примитивов, сервиса — дизъюнкция реплик. Один и тот же ID общего примитива используется во всех зависимых репликах; он не размножается как независимая вероятность. Состояние ребра — конъюнкция его primitive bindings. Неаннотированные рёбра считаются детерминированно доступными только по явному metadata contract.

G — направленный граф сервисов, включая сервисные циклы; span ancestry должна быть ацикличной. В контроле parent ID должен присутствовать; потеря родителя, неизвестный сервис, неполное покрытие или неопределённый тип ребра не угадываются. Повторы одного вызова сохраняют счётчик span links, но логически используют то же статическое состояние. Повтор с независимым состоянием на каждое выполнение не поддерживается. Выбор работоспособного пути идеальный; таймауты переключения, случайный выбор маршрута, нагрузка, очереди, retries и последствия записи не моделируются.

Φ(x)=1, если entry жив и все **объявленные** required services достижимы через живые узлы и sync-рёбра. Async-рёбра не дают immediate достижимости. Optional — сервис, который не является required и не нужен ни одному требуемому пути; optional не выводится просто из отсутствия ошибки span. Eventual и полнота бизнес-ответа остаются другими событиями, не синонимами Φ.

| Сущность | Разрешённый источник / поле | Функция / сохраняемое поле |
| --- | --- | --- |
| Ребро / тип / multiplicity | Контрольные нормализованные spans: trace_id, span_id, parent_span_id, service, edge_type | `build_model`: graph.edges, observed_span_links |
| Реплики, домены, связь | Явные метаданные replicas и edge_gates; primitive ID связывает общую причину | model.replicas, graph.edges[].factors |
| Обязательный результат | Metadata operation.entry/required/semantics | model.operation; `phi` не меняет target set |
| θ_i | Прямая probe values[i] ∈ {False,True,null}; sample_id; измеряемое множество | successes/observed_count/estimate; неизвестное → null |
| Закон наблюдения | direct-primitive-mcar-v1: positive observation probability для measured, маска независима от состояния, не условна на success | observation_law; неподдерживаемая условность отклоняется |
| Вероятность | Только сохранённые G/R/P/Φ и оценки, без исходных observations в replay interface | `solve`, точное перечисление, essential_primitives / status / prediction |

Это **не** разрешение трактовать HAProxy L7 health как прямое наблюдение всех primitive causes. Такая проба обычно является составной функцией процесса, связи и состояния маршрутизации; её закон требуется вывести отдельно. Связь нормализованных контрольных spans с реальным native extractor также ещё не доказана. Ручные θ, истинные injection states, baseline q и проверочные outcomes отсутствуют во входах демонстратора.

## Семантическая линия S1: условие безопасного исключения рёбер

**Условия.** Фиксированы G/R, множество T обязательных целей и произвольный закон состояний P; один и тот же state задаёт живые узлы/рёбра в двух моделях. Пусть D — удаляемые рёбра. Ни одно ребро D не лежит ни на одном простом пути от entry к какому-либо t∈T в исходном графе допустимых для этой Φ типов рёбер. R, P и T при удалении не меняются.

**Утверждение.** Φ_G(x)=Φ_(G\D)(x) для каждого x, следовательно вероятности равны при любом P, в том числе при общих причинах.

**Доказательство.** Удаление не создаёт путей, поэтому успех после удаления влечёт успех до него. При успехе до удаления для каждой цели имеется живой путь; из него можно удалить циклы, получив простой живой путь. По условию он не содержит D и остаётся во втором графе. Обе импликации выполнены для каждого состояния; суммирование с одинаковыми весами P сохраняет равенство. Доказательство не предполагает независимости.

**Контрпример.** Единственный путь к required target проходит по удаляемому async-ребру: при живых узлах all-edge достижимость равна 1, sync-only — 0. Нельзя одновременно удалить этот target и заявить сохранение фиксированного Φ. Аналогично удаление синхронной альтернативной ветви в демонстраторе меняет вероятность 0.9→0.5.

**Проверка и следствие.** Контроли optional_async, async_is_only_required_path_counterexample, remove_only_one_effective_path и deterministic_edge_subdivision_equivalence. Исключать нерелевантную async-ветвь допустимо при доказанном условии; исправление async-семантики вне него — новая модель/предикат с отдельным прогнозом. Для AINA сначала проверяется, выполнено ли условие в конкретных исторических графах; текстовая формулировка не заменяет эту проверку.

Это стандартное свойство графовой достижимости и согласования вероятностей, а не заявленная новая теорема. Оно делает проверяемым условие исключения связей в рассматриваемой цепочке; достаточность этого материала для вклада F ещё не установлена.

## Идентификационная линия I1: параметры и целевая функция различаются

**Условия.** Тот же конечный монотонный Φ, независимые Bernoulli primitives с θ∈(0,1)^d. Для множества O есть прямые наблюдения x_i с положительной вероятностью включения, маски независимы от состояния, их закон известен и не зависит от θ. Остальные примитивы никогда не наблюдаются. Утверждение относится к популяционному закону наблюдений; конечная выборка рассматривается отдельно.

**Утверждение.** Закон наблюдений определяет θ_i для i∈O через P(x_i=1 | i наблюдён). Параметры вне O не идентифицируются. Целевая A(θ)=EθΦ идентифицируется тогда и только тогда, когда каждый существенный аргумент Φ входит в O. Аргумент i существенен, если существуют значения остальных битов, при которых его переключение меняет Φ.

**Доказательство.** Независимость маски даёт условную вероятность θ_i. Закон наблюдаемых значений — произведение наблюдаемых Bernoulli margins с заданной маской, поэтому изменение ненаблюдаемого θ_i его не меняет. Если все существенные аргументы наблюдаемы, Φ не зависит от остальных и A вычисляется из идентифицированных margins. Если ненаблюдаемый i существенен, условимся на остальных битах: производная A по θ_i равна E[Φ(1,X_−i)−Φ(0,X_−i)]. Все разности неотрицательны по монотонности; хотя бы одна положительна по существенности. Каждое состояние X_−i имеет положительную массу при θ∈(0,1)^d, поэтому производная строго положительна. Два разных θ_i дают одинаковый закон наблюдений и разные A. Необходимость и достаточность доказаны.

**Конечная выборка.** Для каждого наблюдаемого primitive частотная MLE — successes/n, без сглаживания. При n=0 оценка отсутствует: population observable не означает наличие данных. `solve` проверяет существенность по всей truth table, поэтому случайная граничная оценка другого параметра не превращает структурную неоднозначность в доказанную идентификацию. При ненаблюдаемом существенном факторе прогноз null; выводимый диапазон — inf/sup по недостающим θ при подставленных известных оценках, **не доверительный интервал**. В этом демонстраторе параметрическая неопределённость не оценена.

**Контрпримеры/контроли.** A=a∨b, θ_a=.8: наблюдение только a не различает θ_b=.25 и .75, но A=.85 и .95. Диапазон plug-in [.8,1]. Если b принадлежит только optional async-ветви, θ_b остаётся неидентифицируемым, но A=θ_a=.8. Все primitive channels объявлены, однако выборка пуста → insufficient_observations. Отдельные B-прогоны с N=20/200, missing rate=0/.5 и фиксированными seeds публикуют ошибки θ и A раздельно; ни одна удачная выборка не выбрана по точности.

Это применение стандартной Bernoulli MLE и аргумента существенности монотонной Boolean-функции. Ближайшие формальные основания: [Comparing Birnbaum importance measure of system components](https://www.cambridge.org/core/journals/probability-in-the-engineering-and-informational-sciences/article/abs/comparing-birnbaum-importance-measure-of-system-components/774AD90C235DC11EE342A1D90B78FA96) и [Rothenberg, Identification in Parametric Models](https://doi.org/10.2307/1913267). Здесь не заявлены ни новая общая теория идентификации, ни достаточность составных probes реальных приложений. Нетривиальный вклад для фактического observation law ещё требует отдельной работы.

Максимальная ошибка 1.1102230246251565e−16 при допуске 1e−12. Присутствуют serial, alternatives, common cause, three replicas, communication, optional/async, repeat, placement, структурное изменение и эквивалентности. Семь B-контролей, пять ожидаемых unsupported и один replay дают 25 проверок. Решатель не использует Monte Carlo. B-выборки — искусственные наблюдения; они не имитируют доказанное распределение native telemetry приложения.

## Первая H-гипотеза и следующие изменения

**H-EXEC-01, кандидат; данных недостаточно.** Мотивирующее отклонение — historical M7 `checkout_cart` OTel: собственная MAE 24.46223 п.п. на 55/80 current cells, при B0 4.79971 п.п. на 80/80 ([census](milestones/M7_COMPLETE_OPERATION_CENSUS.md)). Неравное покрытие запрещает трактовать эти две MAE как paired effect; это выбор направления разработки, не перенос причины на AINA.

Механизм-кандидат: идеальная статическая достижимость расходится с исполнением при переключении/восстановлении и сроке ответа. Различающий признак — failures при существующем живом требуемом пути, связанные с request routing и временем с подтверждённого изменения состояния. Конкуренты: неполная Φ/обязательные сервисы, потеря span контекста, неверный observation law, ошибки самого контракта. Сценарный p AINA известен; неизвестные параметры причиной не назначаются.

Для первого технического примера: на **одной фиксированной версии** приложения сравнить стационарное состояние с одной доступной репликой и переход к тому же состоянию; одинаковые operation mix, deadline, health/probe policy, placement. Отрицательные контроли — обе реплики доступны и нецелевые операции. До самостоятельного H-пакета требуется зафиксировать N независимых кампаний, seeds, расписание interventions, окна агрегации, диагностические state/execution признаки, прогноз направления и интервалы. Пока эти детали не зафиксированы, H-пакет не запускается и причинного результата нет. Изменение маршрутизатора — другая конфигурация, изменение success predicate — другая метрика.

Следующие необходимые работы: (1) подтвердить выбранные historical source bytes; (2) определить реальные составные observations и поддержанный класс с идентификацией целевой функции, а не выдавать их за прямые primitive probes; (3) реализовать native→G/R/P/Φ и технический пример нового метода на каждом приложении; (4) только затем заморозить G0 adaptation/G-ID/≤2 refinements/G*, ablations и H-пакет. Дальнейший main admission — [v3 protocol](MAIN_COMPARISON_PROTOCOL_V3_DRAFT.md).
