# Historical HAProxy prefix audit v1

Frozen before the first run. This is a diagnostic correction census on opened retained evidence, not a new main campaign, model improvement or causal intervention.

Symptom: the legacy health decoders compare literal `check_status` to `L4OK` or `L7OK`. The [HAProxy 3.0 management reference, check_status field](https://docs.haproxy.org/3.0/management.html) defines the `* ` prefix as a check currently running with the last known result. Raw Petclinic ordinary census contains `UP/* L7OK`. Bounded tests reproduce the legacy false path and preserve every other decoding rule.

Correction version `historical-health-prefix-v1` removes exactly this leading prefix before invoking the unchanged legacy decoder. It retains historical Docker Running/Paused, network count, backend status, declared L4/L7 type and empty L4 status handling. These privileged variables are permitted only in this diagnostic; they are not inputs to the ordinary v3 graph method. No new physical interpretation of probes is asserted. Historical source/data/report bytes remain unchanged.

The predeclared census covers every calibration and test health file in the 160 preserved M7 campaigns, and calibration health in all eight qualified Petclinic technical campaigns: 168 identities / 328 files. Petclinic has no previously scored test comparison here. Other auxiliary historical series are outside this audit and require a separate dependency audit if reused. Source artifacts are locked by exact ID/name/run/head/size/SHA256; the M8 preservation contains all 160 M7 qualified cells. Remote download checks API identity, actual ZIP bytes/digest and CRC. Exact read health member hashes and Petclinic learner seals are recorded. No raw archives are stored locally.

Report every identity, period, denominator, raw status census, old/corrected joint patterns, transition counts and changed tick/replica counts. No sampling, selection by effect, fitting, outcome loading, native model parsing, PMX execution or acquisition. A zero-change file provides an exact unchanged-input result for this correction, not a broader validity certificate. Any changed calibration requires versioned refitting of all dependent historical methods/views before using their corrected predictions; changed test health may additionally affect stable-window scoring. Original reports remain labeled with their old decoder. PMX construction does not use this health decoder.

One remote job, timeout 20 minutes, pinned Python/dependencies, retention 90 days including failure output. The resource cap is computational, not statistical power. No inference about error magnitude or scientific causes is made from changed tick counts. Subsequent corrected fits and scoring must use a separate frozen configuration and preserve old/new values, all absences, the full affected census and dependency scope.
