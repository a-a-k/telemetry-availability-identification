# Ordinary identity v2 and joint demand census

The first ordinary projection deliberately whitelisted a small resource set.
Its retained preparation audit shows that `hostname` was excluded from all
3,560 DeathStar spans, and `host.name` from 7,680 OTel spans. This is a limitation
of that projection, not proof that the original traces lacked replica identity.
The frozen v1 artifacts and their reported absent standard instance IDs remain
unchanged. This version extends the permitted ordinary resource schema by exactly
`hostname` and `host.name`; it introduces no Docker health or injection state.

Question: can original native identity, combined with declared replica service
names, resolve observed target-call footprints while preserving the full census?
Freeze code, source artifacts, protocol and schema before remote restoration.
Use the same 4,080 technical/development attempts as the completed execution audit.
No new traffic, independent sample, estimator fit or main campaign is added.

For DeathStar/OTel, restore their exact original normal-contract raw artifacts
and unchanged ordinary v1 artifacts. Normalize the selected native traces with
the original parser and prove that the original projection is reproduced in
every native field before adding the two explicit identity attributes. Requests,
probes and declarations must remain byte-identical. Petclinic already has
explicit replica and instance IDs; its ordinary native values are unchanged.
Every extended ordinary role has a new version and exact file seal.

Binding uses equality to the declared `replicas` service names, which the pinned
placement renderer assigns to the containers' declared hostnames. Native
`study.replica` is also accepted when it is a declared replica. Conflicting native
bindings remain unresolved; no substring/domain stripping, guessed backend or
controller-to-replica reconstruction is allowed. Host identity is an identifier,
not an availability, fault-domain-independence or physical-state observation.
Unmapped values are retained as missing bindings.

Count observed target entries at cross-service parent boundaries. Preserve native
SERVER labels where present. For DeathStar only, the two exact names
`read_user_timeline_server` and `write_user_timeline_server` are explicit entry
annotations justified by `UserTimelineHandler.h` at upstream commit
`6ecb09706140f8730b5385c08f1386c654c3c526`, saved blob
`a1e8f34d8e421e82996b8540424f3c4b88554714`. This source creates those spans on entry
using the incoming trace context; no native kind is rewritten. Other unlabelled
boundaries remain unclassified rather than being accepted by a name suffix.

The complete-contract target-call counts are declared from the operation/source
contracts: DeathStar compose/user-read 1 and home-read 0; OTel browse/cart 1 and
checkout 3; Petclinic owner-details/create-visit 1 and owner/vet lists 0. These
are reference counts for this fixed workload, not imputed calls on failed
executions. Retain all observed multiplicities, unresolved labels, unmatched
boundaries and outcome cohorts. Actual application retries, omitted calls and
partial execution can differ from the reference; count equality alone does not
prove complete reporting or call independence.

Report joint replica footprints and observed route words per external attempt,
with all failures/timeouts. A word's timestamp order is descriptive, with a
span-ID tie break, not causal order. Do not infer an iid routing probability from
call marginals or extrapolate normal-window footprints to a faulted deployment.
No numerical forecast is generated by this census.

Three preparation jobs receive source archives; three physically separate
inspection jobs receive only the six extended ordinary files. The consumer's
read boundary covers seal/schema loading and all calculations, with exactly six
data reads and no network/subprocess/privileged access. Each job has a 10-minute
budget, at most three concurrently within each stage, pinned Python 3.13.15 and
dependencies. Source-transfer and stage process costs are separate; both source
and inspection compact reports, including failures, have 90-day retention.
Full ordinary/native payloads remain remote. Only exact compact reports are
retained locally.

Three bounded tests check exact identity/conflict behavior, byte-equivalent old
native projection before extension, and the source-declared unlabelled entry
adapter with failed/missing calls retained. Application completion requires the
full input census and role checks, not complete routing coverage or a desired
model result. The resulting binding supports subsequent explicit X/D/T model
work; it does not itself qualify capability/timing observations or final G*.
