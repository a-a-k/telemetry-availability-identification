# Исходный формализм и реализованный метод без ML

Версия спецификации 1.0, 8 сентября 2026. Вопрос итерации: какие именно G/R/P/Φ, параметры и предикаты вычисляет текущий код и какие части исходной статьи он не реализует? Проверяемый результат — полная трассировка сущностей/чисел, явные ограничения и воспроизводимые известные контрольные параметры.

Источник определения — авторский `MODELS_NIER_2026.pdf`, разделы 4, 5, 10; [SHA-256 и происхождение](evidence/original-formalism-map-2026-09-08/paper-provenance.json). Исходные `model.py` и `estimators.py` из сопутствующего MODELS-артефакта сохранены без изменения, с MIT-лицензией, в [reference_models/original_stochconn](../reference_models/original_stochconn/model.py). Версия их исходного git commit не установлена; конкретные байты зафиксированы хешами. Они служат исходной вычислительной ссылкой, а не новой версией исторических M7-прогнозов.

## Три разных объекта

1. **Формализм статьи:** `M = ⟨G,R,P,Φ⟩`, `G=(V,E,τ)`, состояния реплик и логических зависимостей; произвольная мера P допускает зависимости. Канонический immediate-предикат проверяет достижимость обязательных целей по живым sync-зависимостям. Полнота бизнес-ответа и временные ограничения требуют явно соответствующего предиката/состояния.
2. **Исходный синтетический вычислитель:** произвольный конечный service graph, типы sync/async, реплики, независимые θ и ρ, reachability и all/any/k-target predicates. Его `ServiceGraph` и перечисление не являются универсальным вычислителем произвольной P. Корреляционные и временные семейства исходной статьи имеют отдельные конструкции; они не возникают автоматически от передачи графа этому API.
3. **Историческая живая реализация M7:** фиксированный шаблон двух путей к двум целевым репликам; одна общая причина для colocated либо две независимые причины с одинаковым параметром для split, независимые коммуникационные факторы, остаточная вероятность каждой операции. Трассы проверяют участие объявленной целевой группы; весь сохранённый dependency graph не поступает в `route_probability`. Это ограниченная инстанциация, а не реализация всех возможностей исходного формализма.

[Полный census](milestones/M7_COMPLETE_OPERATION_CENSUS.md) оценивает третий объект. Прогноз M9N–M9P с временной регрессией — отдельная историческая диагностика, в основной метод этой спецификации не входит.

## Соответствие G/R/P/Φ

| Сущность статьи | Реализация / поле | Источник и автоматизация | Ручная часть / преобразование / граница | Проверка |
| --- | --- | --- | --- | --- |
| V: service types | Исходный `ServiceGraph.services`; в live `learner/requests.csv.services`, `deployment.target_service` | Native service labels извлекаются из разрешённых baseline/calibration traces. | В M7 целевой сервис объявлен; прочие сервисы не имеют отдельных состояний в likelihood. Их совокупный эффект заменён q_u. Это не доказанная редукция произвольного G. | Четыре M9T/M9U сохранённых request inventories; исходный графовый контроль `.792`. |
| E: logical dependencies | `live_evidence._topology_rows` → `learner/topology-edges.csv`; исходный `Edge` | Агрегация native parent/child разных сервисов, поддержка spans/traces. | M7 файл хранит только source/target/support; operation/protocol/kind в ключе теряются. `load_qualified_cell` не загружает этот файл в вычислитель. | Исходники `_topology_rows`, `load_qualified_cell`, `_latent_template`; отсутствие графового поля видно в `QualifiedCell`. |
| τ: sync/async meaning | Исходный `Edge.edge_type`, `ServiceGraph.allowed_edge_types` | В исходном синтетическом графе задаётся явно. | M7 двухпутевой шаблон не читает τ и не обнаруживает Φ из него. Технологическая messaging-метка сама по себе не доказывает неблокирующее бизнес-поведение. | Сбой async-ребра не меняет `.792` immediate; обязательное eventual при том же сбое даёт `0`. |
| R: replica counts and placement | Исходный `replicas`; live `deployment.json.replica_services/domain_assignments` и `target_replicas` в requests | Развёртывание объявляет a/b; instance identifiers из трасс проверяют присутствие обеих реплик. | M7 рассчитан на две реплики. Домены объявлены, причины отказов из identity не выводятся. Обе схемы — логические домены одного runner. | Контроли all_up / no_replica / one_path и минимальная trace-support проверка обеих реплик. |
| Ω_V: replica states | `_health_signal`: H_i = running AND NOT paused | Docker-состояние из learner health; выборка/masking зафиксированы режимом. | Это process-health, не доказательство корректного ответа операции. Фактическое назначение каждого вызова на backend не восстановлено этим сигналом. | Живой процесс с C_i=0 даёт недоступный путь; H_i остаётся 1. |
| Ω_E: dependency states | `_health_signal`: P_i = H_i AND network_count>0 AND backend UP AND check∈{empty,L4OK}; latent C_i | Наблюдаемая доступность proxy/backend и процесса; латентные коммуникационные параметры оцениваются likelihood. | C_a/C_b относятся к двум путям, не к одному общему логическому ребру статьи. Условная модель пути — P_i=H_i C_i; неизвестный/пропущенный span не есть C_i=0. | Два живых процесса, оба коммуникационных пути недоступны → route=0. |
| P: joint state law | `_latent_template`, `_state_probabilities`, `FitCandidate.parameters` | Численная максимизация заявленного masked health/request likelihood по learner-наблюдениям. | Независимы примитивы G,E_a,E_b,C_a,C_b; общая G создаёт зависимость H_a/H_b. В split две независимые G_a/G_b имеют одну оценённую маргиналь g. Не произвольная совместная P. | При g=.8 и прочих параметрах 1: colocated=.8, split=.96. |
| Φ_u: external success | Исторический драйвер → requests.semantic_success; model uses `requires_target_group`, `q_by_operation`, `route=max(P_a,P_b)` | Семантический исход клиента — наблюдение. Participation inferred only from successful supported traces, checked against configured expectation. | Для target-required: Φ≈Q_u AND (P_a OR P_b); для non-target: Q_u. Φ и target requirement объявлены/проверены, не полностью выведены из trace graph. | Известный двухпутевой oracle; полный M7 census показывает эмпирическую границу этого Φ. |
| A_u = E_P Φ_u | `route_probability` exact sum over 32/64 latent states; `predict_cell`: q_u × route or q_u | Расчёт после оценки параметров, без регрессионной поправки прогноза. | Нет Monte Carlo sampling error в M7 этой функции. Есть ошибки оценки параметров, маски, семантики и несоответствия стационарному шаблону. | 12 известных M7 комбинаций с max absolute error ≤1.12e−16. |

## Все численные параметры и выдаваемые вероятности M7

| Величина | Источник / код | Предположения и объявленные значения |
| --- | --- | --- |
| e_a, e_b | `_parameter_names`, `fit_exact_model`, observed learner H/P and request-bin outcomes | Вероятности независимых индивидуальных факторов; оцениваются, а не берутся из расписания инъекций. |
| g | Те же функции при объявленном law с D | Одна общая причина colocated; две iid причины split с тем же параметром. Если D нет, g фиксирован 1: доступно объявление класса fault model, не скрытое открытие его реализации. |
| c_a, c_b | Те же функции при объявленном law с C | Коммуникационные факторы независимы от здоровья и друг от друга. Без C фиксированы 1. Произвольные общие сетевые причины не оцениваются. |
| q_u | `prepare_mode`, `_smoothed_mean`: (S_baseline+0.5)/(N_baseline+1) | Все baseline-исходы этой операции; minimum 20. Это независимая остаточная вероятность, принятая равной её чистой availability. Не условная наблюдённая надёжность каждого прочего компонента. Перенос постоянства q_u является допущением. |
| P(ω) | `_state_probabilities` | Произведение параметров примитивов; нормируется на сумму конечной таблицы. |
| route_current / route_transfer | `route_probability`; `FitCandidate.current_route/transfer_route` | Точное математическое ожидание static OR, тот же набор оценённых параметров. Перенос использует исходное colocated-наблюдение и объявленное разделение домена. |
| prediction proposed | `predict_cell` | q_u×route при подтверждённой target-topology и численном identification guard; q_u для non-target. При неподдерживаемости — пустое значение со статусом. |
| prediction B3 | `predict_cell` | Тот же оптимум и q_u, но без identification guard. Совпадение с proposed на выданных значениях обязательно. |
| prediction B0 | `predict_cell`, `calibration_by_operation` | (S_cal+0.5)/(N_cal+1), все калибровочные попытки, minimum 20; без health-фильтра. При переносе сохраняется частота источника. |
| prediction B1 | `_route_estimates`, `_signal_mean` | q_u×[1−(1−p_a)(1−p_b)] по доступным маргиналям путей; те же topology guards. |
| prediction B2 | `_route_estimates`, `_joint_health_mean`, `_route_mle` | При общей причине: q_u×[p_a+p_b−h_ab c_a c_b], c_i=p_i/h_i с объявленными clipping/epsilon. В split/без D — B1; без совместного health предусмотрен endpoint-route fallback. Это авторский контроль с конкретными предположениями. |
| prediction B4 | `_complete_route_mean`, `predict_cell` | q_u×эмпирическая доля P_a OR P_b на полных health ticks; отказывается от target-required transfer. |
| Численные настройки | `configs/m7_frozen_live.yaml` | Beta α=β=.5; optimizer 8 starts, 1000 iterations, epsilon=1e−5, probability floor=1e−12. Start seed детерминирован campaign/mode; неопределённый параметр не становится определённым от выбора start. |
| Топологические пороги | Та же конфигурация, `infer_topology` | ≥20 retained successful traces; target fraction ≥.8 или ≤.05; ≥5 назначений каждой реплике. Промежуток → abstention. Это ручная замороженная политика допуска. |
| Identification thresholds | Та же конфигурация, `fit_exact_model` | SVD rank tolerance 1e−7; target gradient 1e−6; multistart target range ≤1e−4; minimum pattern count 10. Это численная локальная проверка и multistart diagnostic, не глобальная теорема идентификации произвольной живой модели. |
| Telemetry and time settings | `prepare_mode`, configuration | Бин 1 s, alignment tolerance 1.25 s; full или объявленные health/trace masks. Stable evaluator guard 1 s и 23/46 s block intervals не меняют A_u. В likelihood transition proximity лишь учитывается диагностически, не удаляет все такие исходы. |

При `g=.8,e_a=.9,e_b=.85,c_a=.95,c_b=.9` полиномы дают

```text
A_route,colocated = g [1 − (1−e_a c_a)(1−e_b c_b)] = 0.77274
A_route,split = 1 − (1−g e_a c_a)(1−g e_b c_b) = 0.877392
A_u = q_u A_route
```

Эти равенства относятся к принятой P и static OR. Они не устанавливают, что балансировщик найдёт живой путь до deadline.

## Повторы, время, fallback и общие причины

| Поведение | Что способен выразить исходный формализм | Что реализует M7 / что остаётся ограничением |
| --- | --- | --- |
| Несколько обращений к той же зависимости в одном неизменном состоянии | Один static logical-edge state; повторная проверка той же достижимости идемпотентна. | Повторы и разные backend-назначения не входят в Φ. Умножение независимых per-call вероятностей описывало бы другую P/Ω. |
| Retry, переключение, circuit breaker, hangs | Требуются временные/дополненные состояния и предикаты, как указано в разделе 10 статьи. | В M7 не реализованы; успешный static OR может не завершиться в срок. Регрессионная M9P не является восстановленной частью исходного метода. |
| Необязательная либо асинхронная работа | Явный набор обязательных целей и используемых τ; непосредственный и eventual исходы различны. | У M7 нет универсального τ-aware графового вычисления. Отсутствие target у операции — единственный используемый здесь переключатель. |
| Перехваченная ошибка / пустой fallback | Φ обязан отличать полный результат от деградации; span error не заменяет Φ. | Исторический внешний M7 oracle сохранён. Полнота Petclinic и новые десять контрактов ещё требуют контроля. |
| Общий домен отказа | Произвольная зависимая P допустима синтаксисом статьи. | Одна конкретная факторная P поддерживает colocated versus split; произвольные общие причины не выведены из данных. |
| Ошибка связи при живом процессе | Логическое ребро остаётся отдельным состоянием. | H_i и P_i различаются; C_i моделирует конкретный replica path, а не все зависимости приложения. |
| Общий логический bottleneck перед всеми репликами | Одна ε_e перед сервисом не устраняется ростом R. | M7 C_a/C_b независимы: такой общий сетевой bottleneck здесь не представлен отдельным фактором. Синтетический исходный oracle: [1−(.1)^2]×.8=.792. |

Отсутствие поддержки корректно описанной семантики — ограничение реализации. Ошибка определения или скрытое изменение Φ было бы дефектом протокола. Большая правильно измеренная MAE сама по себе не является программным дефектом.

## Граница данных и отсутствие ML

Путь прогноза M7: qualified learner records → `prepare_mode` → `fit_exact_model` → `predict_cell`. Используются счётчики, явное конечное пространство состояний, точный likelihood и численная оптимизация его вероятностей. Ни логистической регрессии, ни коэффициентов M9N–M9P, ни обучаемой поправки итогового A_u на этом пути нет.

При этом исторический `load_qualified_cell` читает learner **и evaluator** в одном процессе до анализа. Рассмотренные fit/predict-функции используют learner-поля, но это не доказательство требования «ноль чтений проверочных файлов». Поэтому для новой серии этот combined loader недопустим. Уже существующий `_load_learner_cell` возвращает пустые test tuples и используется отдельной M9V candidate job; новый pipeline должен физически не выдавать ей проверочные артефакты и журналировать доступ. Открытые старые исходы остаются данными разработки.

У snapshot-прогноза нет информации о будущих конкретных fault times или test health. Категория допустимого fault model, размещение, workload operation и настройки — объявленные метаданные, которые учитываются отдельно от измеренных параметров. Факт того, что sampler принимает параметры, не доказывает, что эти параметры идентифицированы или адекватны.

## Контроли и воспроизведение

Команда из корня репозитория:

```text
python scripts/check_original_formalism_map.py
```

Она выполняет 12 известных двухпутевых расчётов (all-up, no-replica, one-path, живой процесс с ошибкой связи, общий домен, смешанные параметры × два размещения) и три проверки исходного графового вычислителя (логический edge bottleneck, неблокирующий async-сбой, обязательный eventual-сбой). [Результаты и исходные хеши](evidence/original-formalism-map-2026-09-08/controls-and-source-hashes.json). Ни один параметр не оценён по результату модели; native-данные и ML не используются. Ранее прошедшие 16 положительных M9S и 44 M9U oracle records сохраняют свою область и не повторяются.

## Следствие для новой серии

Спецификация делает ограничения M7 проверяемыми и не изменяет его результаты. Основной будущий метод должен иметь собственную версию сериализованных G/R/P/Φ, явные источники параметров, тот же внешний deadline/outcome, и публиковать ограничения временной/состояниевой семантики. Нельзя заявлять, что M7 полностью восстановил типизированный граф и его произвольный success predicate: такого пути кода здесь нет. Если продолжение использует этот ограниченный M7-класс как первичный вариант, его нужно назвать и зафиксировать именно так; если вводится немашинное расширение, оно получает другую версию, известные контрольные примеры и отдельную проверку после заморозки.

Следующее действие текущего плана — завершить PMX request/context mapping и квалифицировать Petclinic; основной вариант трёхприложенной серии фиксируется по семантическим основаниям до открытия новых результатов.
