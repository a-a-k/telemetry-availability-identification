# SIMPAT: чек-лист после каждой итерации

Версия 1.0, 8 сентября 2026 года. Используется вместе с [планом-корректировкой](SIMPAT_CORRECTION_PLAN.md). Файл задаёт порядок контроля; автоматический запуск проверки в репозитории этим документом не установлен.

## Правило применения

Итерация — завершённое изменение модели, кода, адаптера, стенда, данных, протокола, анализа или текста утверждений, а также завершённый запуск либо пакет запусков.

1. До начала записать вопрос, ожидаемый проверяемый результат и затрагиваемые критерии.
2. После завершения пройти весь список C01–C22. Неизменившиеся доказательства можно переиспользовать по точной ссылке; повторять все вычисления не требуется.
3. Для каждого критерия записать статус, доказательство, выявленное ограничение и следующее действие, если оно нужно. Пустые статусы запрещены.
4. Зафиксировать влияние изменений на прежние результаты: что остаётся действительным, что нужно пересчитать, какие данные после просмотра исходов стали данными разработки.
5. Закрыть итерацию коротким отчётом: что изменилось; какие числа или проверяемые факты получены; что остаётся неизвестным; одно следующее действие. При длительной итерации сообщать текущее препятствие и состояние работы, не дожидаясь её завершения.

Статусы: **ПРОВЕРЕНО** — есть соответствующее доказательство; **ОТКЛОНЕНИЕ** — установлен конкретный дефект протокола или реализации; **НЕ ПРОВЕРЕНО** — доказательство ещё не получено; **Н/П** — неприменимо к этой итерации, с причиной и ссылкой на последнее действительное состояние, если оно существует.

Большая ошибка прогноза, широкий интервал, меньшая скорость и отсутствие поддержки отдельного случая — научные результаты. Они не являются статусом «ОТКЛОНЕНИЕ», если измерены и отражены корректно. Н/П не закрывает обязательство общего плана; оно только обозначает область текущей итерации.

## Критерии и требуемые доказательства

| ID | Что проверять | Доказательство и конкретное условие |
| --- | --- | --- |
| C01 | Предмет и ограничения метода | Путь основного прогноза и список зависимостей: нет ML-предиктора, регрессионной поправки или коэффициентов из M9N–M9P. Оцениваются параметры заявленной стохастической модели. |
| C02 | Соответствие исходному формализму | Таблица G/R/P/Φ → модуль/поле → источник → ручная часть → ограничение → контрольный пример. Все выдаваемые параметры и вероятности прослеживаются; изменения предикатов имеют версию. |
| C03 | Исторические результаты | Учтены 160 кампаний M7 и 480 сочетаний «кампания × операция», включая отсутствующие прогнозы. Повторный анализ checkout не прибавлен как независимый эксперимент; временная ML-диагностика отделена. |
| C04 | Все операции и семантический успех | Есть 10 контрактов: 3 DeathStarBench, 3 OpenTelemetry Demo, 4 Petclinic. У каждого указаны начало/конец, все HTTP-действия, численный deadline, полный успех, деградация и отказ; HTTP 200 не заменяет смысловой результат. |
| C05 | Попытки и соответствие трассам | Контрольное число попыток совпадает с журналом клиента: ноль потерянных и задвоенных идентификаторов. Отсутствующая трасса не удаляет попытку; несколько корней не увеличивают знаменатель. Преобразования адаптера раскрыты. |
| C06 | Корректность Petclinic | Зафиксированы версия, образы, конфигурация и fallback; две реплики Visits видят одну БД. Четыре операции проверены на контрольных сущностях. Чтение и запись не мешают ожидаемым исходам; запись после таймаута отражается отдельно. |
| C07 | Контрольная семантика отказов | Пройдены применимые случаи из пункта 5 плана: в том числе живой процесс с ошибкой связи, общий отказ, повторы, потерянная трасса, проглоченная/распространённая ошибка, таймаут, неполный ответ. Ожидания получены из контракта, а не из результата модели. |
| C08 | Корректность вычислителей | Сохранены доказательства 16 положительных контролей M9S с допуском 1e-12; новые конструкции имеют дополнительные обоснованные проверки. Для контрольных примеров параметры известны независимо от оценивателя. Исключение и нулевая масса не превращены в нулевую доступность. |
| C09 | Независимость PMX/Palladio | Манифест входов и путь построения подтверждают отсутствие импорта нашего графа, параметров и оценивателя. Основной вариант PMX выбран до проверочных исходов; семантические адаптации и ручные действия перечислены. |
| C10 | Честность сравнений | Сопоставляются одно внешнее событие, deadline, период и допустимый пул данных. Использованные сведения раскрыты по методам. Истина — наблюдаемые исходы; B2 не подменяет истину и не назван стандартом без источника. |
| C11 | Зафиксированный новый протокол | Есть версия манифеста: 3 × 2 × 4 × 10 = 240 кампаний; 800 сочетаний «кампания × операция» на метод; смесь нагрузки, периоды, seeds, fault-параметры, исключение технического пакета. Объём назван ресурсным бюджетом, а не гарантией мощности. |
| C12 | Разделение разработки и проверки | Модели, параметры и прогнозы зафиксированы до открытия проверочных исходов. Нет чтений проверочных health, исходов и расписания инъекций при идентификации. Файлы и артефакты имеют хеши, а порядок доступа подтверждён журналом/изоляцией. |
| C13 | Учёт всей новой серии | Все 240 идентификаторов и все 800 сочетаний на метод имеют статус: прогноз, обоснованный отказ выдавать прогноз либо технически незавершённый случай. Повторы связаны с исходной попыткой; не увеличивают независимый n. Незавершённость не выдаётся за результат метода. |
| C14 | Метрики и интервалы | Показаны наблюдение, прогноз, signed error и MAE в процентных пунктах; дополнительные Brier и распределение абсолютной ошибки; число кампаний и попыток. Bootstrap сохраняет кампанию целиком и парность методов; параметры анализа взяты из пункта 8 плана. |
| C15 | Покрытие и отсутствие выборочного отчёта | Таблицы охватывают все 10 операций, 3 приложения и условия. Покрытие каждого метода и общая область сравнения видны рядом с точностью. Неподдерживаемые и неудобные случаи не удалены; весь поток и stable-подвыборка различаются. |
| C16 | Перенос размещения | Прогноз целевого размещения использует только исходные наблюдения и объявленное изменение. Ноль чтений целевой калибровки/health; опубликованы ошибка целевой доступности, ошибка изменения, покрытие и предположение о домене. |
| C17 | Легковесность и автоматизация | По методам измерены извлечение/идентификация/решение/обновление, память, использованные данные и ручные действия; общая часть учтена один раз. Неизмеренное время не равно нулю. Вывод о нагрузке мониторинга требует отдельного парного измерения. |
| C18 | Исправления и действительность результатов | Есть запись симптом → воспроизведение → причина/гипотеза → изменение → затронутые артефакты → проверка. Исходные результаты сохранены; пересчитаны все затронутые случаи. Изменения по открытым исходам не названы независимым подтверждением на тех же данных. |
| C19 | Воспроизводимость | Зафиксированы commit кода и приложений, зависимости/образы, конфиги, команды, seeds, версии моделей и артефактов. Сводные числа пересчитываются из сохранённых данных; неизвестные версии явно отмечены. |
| C20 | Ограничение пустых ответвлений | У итерации есть вопрос и новый проверяемый результат либо точная причина его отсутствия. После двух итераций без новых доказательств по одному препятствию изменён способ проверки. Новое приложение/семейство методов не добавлено вместо запланированного отчёта. |
| C21 | Утверждения статьи | Каждому утверждению соответствуют таблица/доказательство, область действия и источник сравнения. Нет «не хуже» из одной незначимой разницы, новизны из переименования, успеха/провала статьи из одной метрики или переноса возможностей одного адаптера на весь Palladio. |
| C22 | Отчётность и завершение | Запись итерации заполнена по всем C01–C22; действительные доказательства связаны ссылками. Для финального цикла существует весь пакет пункта 10 плана, включая численный разбор, стоимость, ограничения и неисправленные препятствия. Зелёные джобы не подменяют итоговый отчёт. |
