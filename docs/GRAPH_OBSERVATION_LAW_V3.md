# V3: граф и совместный закон наблюдаемых эффективных состояний

Следующий ограниченный вариант после direct-primitive демонстратора — `graph-observation-law-v1`. [Код](../src/telemetry_availability/graph_observation_model.py), [пять контролей](../tests/test_graph_observation_model.py). Это ещё не admitted G*; прикладных fit этой версии на момент спецификации нет.

## Объект и измерительный смысл

G/R/Φ остаются явными и реально используются при обходе графа каждого состояния. Допускаются произвольный направленный граф, обязательные цели, OR реплик/AND gate coordinates, общие coordinates и до 16 эффективных бинарных сигналов. Φ — достижимость всех declared targets через живые узлы/sync-рёбра. Тип edges, required targets и replica bindings не выводятся из наличия span автоматически.

P теперь допускает **произвольную зависимость** эффективных координат. Он не заменяется произведением эмпирических marginal probabilities. В первой предполагаемой Petclinic привязке координаты — последние объявленные HAProxy verdicts готовности a/b; они включают работу наблюдателя, связь и service readiness, а не прямые физические primitive causes. Это ограничение должно быть в metadata каждой прикладной модели.

Наблюдение O=(M, X_M): mask и известные координаты X; пропуски допускают зависимость от состояния. Данные — частоты категорий O, включая пропуски; ни их удаление, ни MCAR completion не выполняются. Идентифицируется целевая функция EΦ(X) при этих наблюдениях, а не произвольная декомпозиция на domain/process/network причины.

При полном наблюдении в каждом tick эмпирический joint law оценивается частотами состояний. При неполном — оценивается закон O, а совместный latent law не выбирается произвольным способом. Uniform tick frequencies описывают данные калибровочного окна; переход к будущему окну требует объявленной стабильности распределения/режима. Зависимость tick во времени не игнорируется заявлением об iid confidence interval: этот технический вариант CI не рассчитывает.

## I3: точные границы функционала по категориям наблюдений

**Условия.** Конечное X∈{0,1}^d и фиксированный Boolean Φ графа. Известен популяционный закон Q(O); для каждой категории o непустое множество F(o) состоит из полных состояний, согласованных с её mask/values. Никаких ограничений на совместную зависимость X и M сверх этой согласованности не вводится. В частности mask не обязана быть MCAR.

**Утверждение.** По всем совместным законам (X,M), согласованным с Q, точные границы A=EΦ(X):

L=Σ_o Q(o) min_{x∈F(o)} Φ(x), U=Σ_o Q(o) max_{x∈F(o)} Φ(x).

Целевой функционал идентифицируется тогда и только тогда, когда Φ постоянна на F(o) для каждой категории с Q(o)>0. Уникальность P(X) или физических primitive parameters для этого не требуется.

**Доказательство.** Условное E[Φ(X)|O=o] лежит между минимумом и максимумом на F(o). Усреднение по Q даёт границы. Для достижения нижней границы в каждой категории назначим всю условную массу на произвольное minimizer state; для верхней — на maximizer. Эти выборы создают согласованный совместный закон (X,M) и сохраняют Q, поэтому обе границы sharp. Разность U−L — сумма неотрицательных слагаемых; она равна нулю ровно при равенстве min/max для каждой категории положительной массы. Доказательство завершено.

**В коде.** `identify` сохраняет категории/частоты, graph/R/operation и все assumptions. `evaluate` перечисляет состояния графа через `phi`, строит каждое F(o) и суммирует Fraction(count,N) × min/max. При L<U prediction=null; выводятся lower/upper и их точные рациональные значения. При L=U — point graph probability. Результат назван `singleton_given_empirical_observation_law`: отсутствие некоторой категории в конечной выборке не доказывает её нулевую популяционную вероятность. Plugin range не CI; finite-sample uncertainty и adequacy остаются отдельными.

**Контроли.** Для двух полностью коррелированных доступных путей с joint P(11)=.7, P(00)=.3 вероятность OR=.7; подмена независимыми margins дала бы .91 и тест это различает. Категории (1,?) и (0,?) по .5 дают [.5,1] с явно достижимыми концами; единственная категория (1,?) даёт target=1 при неизвестном втором параметре. Удаление существенной ветви графа меняет известный ответ 1→.2, перестановка рёбер сохраняет его. Это exact small controls, не новая application sample и не Monte Carlo.

Это стандартный finite conditional-support аргумент, применённый к явному графовому функционалу. Он не объявляется новой общей теорией частичной идентификации. Новизна F/I для всей статьи и достаточность реальных probe semantics ещё требуют отдельного обоснования.

## Условие семантической редукции и граница business success

Чтобы этот расчёт давал точную вероятность внешнего Y, требуется для всех допустимых физических execution states w: Y(w)=Φ_graph(h(w)), где h переводит их в эффективные coordinates, и закон h(W) соответствует оцениваемому. Тогда равенство вероятностей следует непосредственно суммированием. Если условие не выполнено, graph probability остаётся приближением, ошибка которого измеряется в прикладной проверке.

Для Petclinic необходимо явно рассмотреть: совпадает ли readiness verdict с возможностью успешно обслужить вызов, успевает ли routing/failover уложиться в 2 s, обязательны ли наблюдаемые вызовы для полного результата, и можно ли считать неинъецируемые Gateway/DB states постоянными в данном классе. **Последнее не является измеренной независимой доступностью 1**: если такая редукция используется, её детерминированные предположения перечисляются, сохраняются узлы/рёбра и проверяются границы. Baseline residual q не добавляется скрыто. Калибровочные success labels не подставляются как единственная state variable вместо графа.

## Исправление чтения HAProxy до прикладной привязки

Pinned Petclinic proxy — HAProxy 3.0 image digest из runtime config. [Официальный management guide 3.0](https://docs.haproxy.org/3.0/management.html#9.1) описывает prefix `* ` в check_status как текущую проверку с последним известным результатом. Новый `probe_verdict` сохраняет phase flag и last completed status отдельно: UP + `* L7OK` остаётся известным положительным L7 verdict; DOWN — отрицательная proxy eligibility; неизвестная/неподдержанная комбинация даёт null, не 0. UP/L4OK не становится успешной L7 проверкой.

В двух NCD inventories found UP/`* L7OK`: colocated 27/901 ticks у каждой реплики, split 23/901 и 27/901. Старый `isolated_stochastic_fit.health_signal` отвергает prefix; аналогичное exact-string сравнение есть у historical M7 L4 decoder. **Величина влияния на fitted probabilities/MAE по одним частотам статусов неизвестна.** Нужны отдельная версия исправленного historical decoder, аудит всех affected datasets и пересчёт затронутых fits/metrics; оригиналы сохраняются. Нельзя объявлять это установленной причиной физических failures или общим объяснением AINA deviations. PMX не использует эти health fields; ordinary export сохранил raw strings и исправления bytes не требует.

Другая граница: Petclinic native inventory показывает ровно один missing parent на внешнюю попытку. Контракт создаёт header parent ID `SHA256('client:'+request_id)[:16]`; при native graph build требуется проверить это равенство для каждого missing boundary parent. Только подтверждённые external roots относятся к объявленной границе клиента; иные missing parents остаются extraction uncertainty.

Следующий результат: remote technical build/replay одного `create_visit` graph model для colocated/split NCD с этой наблюдательной семантикой, actual ordinary-only reads, сохранёнными assumptions и expected structural/equivalence checks. Из него не следует main admission для трёх приложений или принятие этого варианта как окончательного G*.
