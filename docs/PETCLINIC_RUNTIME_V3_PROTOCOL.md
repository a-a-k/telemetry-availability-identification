# Petclinic v3: проверка прикладной готовности при резервировании

Вопрос до запуска: обеспечивает ли HTTP health check объявленную маршрутизацию к доступной из двух реплик, сохраняя прежние semantic contracts и другие настройки? Ожидается прохождение обоих one-path контролей и всех остальных 192 попыток, с независимой проверкой proxy states и конкретным TCP/HTTP counterexample.

v2 run 34200559774/head a1d0d4c07acb611777af171e2613cb6921dffc9d завершил все 192 попытки: normal/recovered 32/32, обе контрольные операции 96/96, all-down и communication правильно дали по 0/8 полных карточек/подтверждённых записей. Все native gates прошли: 192/192 связаны с Gateway, обе replica identities, чистый parse, нет конкурирующих Zipkin/Micrometer ошибок. Не прошли ровно два one-path случая: при paused b карточка 0/8 и запись 8/8; при paused a карточка 8/8 и запись 0/8.

Сохранённые трассы показывают обращения именно к paused replica: последовательный round-robin попадал в неё на каждом втором типе операции. HAProxy использовал TCP connect health; пауза user-space не тождественна отказу TCP handshake. Исходная v2 конфигурация поэтому не обеспечила заявленное 1-out-of-2 routing. Это конкретное ограничение конфигурации и допущения о failover, а не повод объявить такие запросы успешными. Все исходные timeout/side-effect outcomes сохраняются.

Отдельный v3 runtime меняет только HAProxy health check на `GET /actuator/health`, ожидает HTTP 200, interval/timeout 500 ms, fall/rise=1. Выбор основан на проверке действительной прикладной готовности, до stochastic/main данных. Источник Java, exact retained image, common MySQL, DTO v2, deadline 2 s, retries/circuit breakers, network fault sequence и все thresholds сохраняются. На каждом контрольном состоянии сохраняется HAProxy stats CSV. При one-path состояниях отдельно проверяется живой TCP connect к paused replica и отсутствие своевременного HTTP health response; эти служебные probes явно отделены от 192 бизнес-попыток.

Повторяются все затронутые шесть deterministic controls и весь native census; нормальные контракты не ослабляются. Восемь stochastic условий запускаются только после квалификации. HTTP health traffic входит в общий объём телеметрии/затраты; без отдельной off/on пары monitoring overhead не заявляется. Неполные или ошибочные варианты остаются в correction log и не включаются в main n. Изменение не распространяется задним числом на старый M7 или его результаты.
