# Основная comparative series — проект до фиксации qualification acceptance

**Статус: draft, запуск main этим документом не разрешён автоматически до реализации и прохождения перечисленных gates.** Авторский объём принят без изменения: 240 campaigns, 800 campaign×operation cells на метод. После получения последних acceptance artifacts этот документ и machine-readable config замораживаются отдельным commit; outcomes будущей основной серии ещё отсутствуют.

Вопрос: как исходный no-ML stochastic specialization и независимый PMX/Palladio предсказывают полный внешний success десяти операций в трёх приложениях при разных зависимостях отказов и логических размещениях, с каким coverage, source-only transfer error и полной стоимостью pipeline? Успех исследования определяется корректностью/полнотой данных и проверок; superiority не предполагается.

## Матрица и новые данные

3 приложения: DeathStar (3 операции), OTel (3), Petclinic (4). Для каждого — colocated/split × N/NC/ND/NCD × repetitions 0…9 = 80 campaigns. Baseline 60 s + calibration 900 s + test 900 s, 4 внешних operations/s, ровный фиксированный operation mix с заранее вычисленным shuffle. Новая base seed **771601**, analysis observation seed **771401**, bootstrap seed **771602**, namespace publication-main-v1-RUN-aATTEMPT. Они отличаются от M7, M9P, Petclinic technical и contract controls. Все десять contracts в отдельной таблице: общий 2 s deadline, correct prerequisites/full required result, один внешний ID на всю sequence.

Renewal laws и их source config сохраняются из квалифицированного M7 acquisition engine: individual min-up12+Exp(mean23), down U[5,9]; communication min-up20+Exp(mean35), down U[4,8]; domain min-up30+Exp(mean45), down U[6,10]. N — independent replica pauses, C — application communication disconnection, D — jointly paused members of declared logical domain. Общие и индивидуальные causes складываются как union, не взаимно стираются. Это параметры **генератора**, доступны acquisition, запрещены fits. Известна категория закона/размещение, а не времена будущих событий или generating rates.

60/900/900 s дают 7440 внешних attempts/campaign и 1,785,600 по полной серии: baseline 57,600, calibration 864,000, test 864,000. Операция DS/OTel имеет 80 baseline и 1200 calibration/test attempts; Petclinic — 60 и 900. Дополнительные readiness/sentinels/persistence audits маркируются отдельно и не увеличивают n. Petclinic inter-period recovery 70 s, trace flush 20 s; прежние приложения используют уже квалифицированные recovery/flush settings. Все домены логические на одном физическом runner/campaign; нет claims о независимых физических машинах.

## Модели и изоляция

Original methods B0/B1/B2/B3/proposed/B4 в full и sampled_mixed; unchanged finite-state MLE/identification thresholds, q Beta(0.5,0.5). Primary proposed — исходная модель без temporal/logistic regression. Полная карта original G/R/P/Φ и narrow implemented class обязательна: two-path state, declaration of other dependencies absorbed jointly in baseline q, не general typed graph. Health L4/L7 декодируется по явному deployment contract, original values не переписываются.

PMX_inclusive — штатная inclusive error parameterization. **Primary comparator PMX_conditional_local** выбран до main по семантике propagated/local errors; применим только при native propagation/positive-support qualification. Swallowed-child errors не переписываются, отсутствие forecasts остаётся отсутствием. DB-client version используется только для наблюдаемых Petclinic MySQL CLIENT calls, source-native PMX projection для остальных приложений. Обе PMX версии строятся независимо по отдельному native-calibration artifact без нашего graph/health/parameters/predictions. Наличие обоих вариантов обязательно, общий ranking разных coverage запрещён.

Acquisition выдаёт физически отдельные learner, PMX-native и evaluator artifacts, каждый с head/namespace/identity/actual file hashes. Наш fit process проверяет строгий allowlist и фактические read paths; PMX job получает только native-calibration role. Ни один test outcome/test health или injection schedule не читается до seal всех candidates. Evaluator download находится в downstream job с dependency на завершённую candidate freeze. В частности нельзя использовать исторический combined M7 loader.

Full current census: 800 cells × 8 methods = 6400 slots. Sampled_mixed шести original methods — отдельно 4800 diagnostic slots. Every slot содержит finite forecast либо машинно-читаемую причину absence; minimum support/topology/identification/PMX unsupported/errors различаются. Qualified source failures тоже остаются в attempted-campaign census, не заменяются нулевыми вероятностями.

## Accuracy и uncertainty

Primary view — все внешние test attempts, включая transition/deadline failures. Stable historical view вторична, рядом с долей retained requests. Для каждого forecast: signed bias p−observed (pp), absolute error (pp), Brier по всем бинарным attempts. По приложению/операции/условию: MAE, signed mean, p50/p90 absolute error, forecast count/denominator и coverage. Операции и условия получают равные веса; большие request counts не дают одному приложению больший вес.

Три planned primary contrasts — application-wise MAE(proposed) − MAE(PMX_conditional_local), только на общей области. Primary full-application campaign contrast требует forecast обоих методов для всех операций этой campaign. Рядом обязательно показываются complete-campaign count/80, operation-cell common count/240 или /320 и собственное coverage. Если условие не имеет ни одной полной пары, соответствующий full-application primary contrast **не оценивается**, не подменяется сравнением других операций/варианта PMX. Secondary partial common-operation comparisons явно названы и не трактуются как full-application result.

10000 paired campaign bootstrap resamples внутри восьми application conditions, кластеризация сохраняет все методы/операции одной campaign вместе. Equal-condition mean complete paired campaign differences. Для трёх primary contrasts — отдельные two-sided **98.333333%** percentile CI, α=.05/3. Остальные CI 95% descriptive. Ни request-level resampling, ни independent resampling разных методов. Bootstrap computation/report должны явно обрабатывать absence/zero common coverage. Nonsignificance не является эквивалентностью; non-inferiority margin не выбран и NI claim не делается.

## Перенос и стоимость

Transfer обучается только на colocated calibration, получает объявленное изменение a/b logical domain placement и выдаёт forecast split. Target calibration запрещена физически, даже для выбора параметров. Pairing app/law/repetition даёт 120 source/target campaign pairs и 400 operation cells/method. Считаются target forecast error и change error: (p_split_transfer−p_colocated) − (observed_split−observed_colocated), coverage рядом. Original homogeneous iid new-domain marginal g assumption называется явно. У PMX native extracted model нет отдельно идентифицированных logical-domain failure parameters; transfer capability нельзя получить подстановкой наших/oracle probabilities. Поддерживаемый transfer или explicit unsupported должен быть определён кодом/контролями до main; source persistence, если показана, называется отдельной persistence оценкой.

Стоимость измеряется по стадиям: shared acquisition один раз; build/restore, extraction, fit, solve, source-only update/transfer, wall, peak RSS, input/output bytes и реальные manual actions. Waiting/failed development runs и холодная сборка приводятся отдельно от steady workflow. Unknown не равен zero. Monitoring overhead требует off/on measurement, scalability — size series; без них соответствующих claims нет. Номинальные observation windows требуют **124 runner-hours**; 20 parallel jobs дают минимум 6h12 только на эти окна, сверх которых идут setup/recovery/telemetry/artifact processing. Фактическая оценка полного бюджета дополняется восьмиусловным technical package до dispatch. Это resource design, не power guarantee.

## Gates, отклонения и завершение

До main: Petclinic runtime/SQL startup acceptance; все восемь technical acquisitions; isolated no-ML fits/read audit; шесть updated DS/OTel live contract checks; независимые новые DB construct controls и 32 Petclinic PMX current cases; все frozen/source/CI checks. Dynamic datasets не меняют thresholds или candidate model family по наблюдённой accuracy.

Сбой до measurement допускает восстановление строго той же planned identity/seed после установленной infrastructure cause; весь первоначальный failure retained. Изменение oracle/representation требует versioned correction и пересчёта всех затронутых результатов на сохранённых исходниках. После получения test outcomes нельзя менять состав main series или добавлять repetitions ради нужного знака/CI. Две итерации без нового доказательства требуют смены подхода, а не повторения прежнего действия.

Завершение: все 240 planned identities учтены, все 800 cells/method имеют forecast или explicit absence, candidate/evaluator seals и actual archive hashes verified; полный current/transfer/coverage/cost report; correction history; checklist C01–C22 после каждой завершённой итерации; claim↔evidence ledger и законченный manuscript package с ограничениями. Старые 160 M7 и 120 M9P сохраняют отдельные denominators. Незакрытые gates не помечаются выполненными этим draft.
